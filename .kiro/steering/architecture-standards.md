## Multi-Tenancy Architecture# Architecture Standards  ## Multi-Tenancy Architecture  The AI Grading System is built as a multi-tenant SaaS platform using row-level security (RLS) and logical tenant isolation.  ### Key Principles  - **Logical Tenant Isolation**: Each institution is a separate tenant with isolated data via PostgreSQL RLS policies - **Shared Infrastructure**: Single database and application instance serves all tenants (cost-efficient, easier deployment) - **Data Isolation**: Tenant ID is a first-class citizen in all domain models and database schemas - **Connection String per Tenant**: Optional tenant-specific configuration for white-label deployments  ### Database Multi-Tenancy Pattern  `sql -- All tables include tenant_id as part of the primary key or indexed constraint CREATE TABLE institutions (   id UUID PRIMARY KEY,   tenant_id UUID NOT NULL,   name VARCHAR(255),   domain VARCHAR(255),   UNIQUE(tenant_id, domain) );  CREATE TABLE users (   id UUID PRIMARY KEY,   tenant_id UUID NOT NULL,   email VARCHAR(255),   UNIQUE(tenant_id, email) );  -- Row-Level Security (RLS) policy example ALTER TABLE institutions ENABLE ROW LEVEL SECURITY;  CREATE POLICY tenant_isolation ON institutions   USING (tenant_id = current_setting('app.current_tenant_id')::uuid); `  ### Application Layer Multi-Tenancy  - All NestJS controllers must accept 	enant_id from headers or JWT claims - Middleware to set pp.current_tenant_id context for the request - All repository queries must filter by tenant_id - Never rely solely on database RLS; enforce tenant_id at application layer  ### API Design Pattern  ` POST /api/v1/institutions/{institution_id}/courses Headers:   Authorization: Bearer {token}   X-Tenant-ID: {tenant_id} Body: { name, description, ... } Response: { id, tenant_id, name, ... } `  ---  ## API Design Standards  ### RESTful Endpoint Structure  - **Resource endpoints**: /api/v1/{resource} or /api/v1/{institution_id}/{resource} - **Actions**: Use standard HTTP methods (GET, POST, PUT, DELETE, PATCH) - **Filtering/Pagination**: Query params (e.g., ?page=1&limit=20&status=active) - **Versioning**: API version in path (/api/v1/, /api/v2/)  ### Response Format  All endpoints return a consistent response envelope:  `json {   "success": true,   "data": { /* resource or array */ },   "error": null,   "pagination": { "page": 1, "limit": 20, "total": 100 } } `  Error responses:  `json {   "success": false,   "data": null,   "error": {     "code": "UNAUTHORIZED",     "message": "User does not have permission to access this resource",     "details": {}   } } `  ### HTTP Status Codes  - 200 OK: Successful GET, PUT, PATCH - 201 Created: Successful POST (resource created) - 204 No Content: Successful DELETE or empty response - 400 Bad Request: Validation error - 401 Unauthorized: Missing or invalid authentication - 403 Forbidden: Authenticated but lacks permission - 404 Not Found: Resource not found - 409 Conflict: Resource conflict (e.g., duplicate email) - 422 Unprocessable Entity: Semantic error (e.g., invalid state transition) - 429 Too Many Requests: Rate limiting - 500 Internal Server Error: Unexpected server error - 503 Service Unavailable: Dependency unavailable (AI service, plagiarism service)  ---  ## Database Schema Patterns  ### Tenant-Aware Tables  Every table should include: - 	enant_id UUID NOT NULL - Foreign key to institutions - id UUID PRIMARY KEY - Global unique ID - created_at TIMESTAMP DEFAULT NOW() - Audit trail - updated_at TIMESTAMP DEFAULT NOW() - Audit trail - deleted_at TIMESTAMP NULL - Soft delete support  ### Example Pattern  `sql CREATE TABLE assignments (   id UUID PRIMARY KEY DEFAULT gen_random_uuid(),   tenant_id UUID NOT NULL REFERENCES institutions(id),   course_id UUID NOT NULL REFERENCES courses(id),   created_by_user_id UUID NOT NULL REFERENCES users(id),   title VARCHAR(255) NOT NULL,   description TEXT,   assignment_type VARCHAR(50) NOT NULL, -- enum: essay, code, quiz, short-answer, file   point_value DECIMAL(10, 2) NOT NULL,   rubric_id UUID REFERENCES rubrics(id),   allow_incremental_submissions BOOLEAN DEFAULT FALSE,   soft_deadline_at TIMESTAMP,   hard_deadline_at TIMESTAMP,   published_at TIMESTAMP,   created_at TIMESTAMP DEFAULT NOW(),   updated_at TIMESTAMP DEFAULT NOW(),   deleted_at TIMESTAMP NULL,   UNIQUE(tenant_id, course_id, id),   CONSTRAINT valid_deadlines CHECK (soft_deadline_at IS NULL OR hard_deadline_at IS NULL OR soft_deadline_at <= hard_deadline_at) );  CREATE INDEX idx_assignments_tenant_course ON assignments(tenant_id, course_id); CREATE INDEX idx_assignments_course ON assignments(course_id); `  ### Audit Trail Pattern  Track all significant changes:  `sql CREATE TABLE audit_logs (   id UUID PRIMARY KEY DEFAULT gen_random_uuid(),   tenant_id UUID NOT NULL REFERENCES institutions(id),   event_type VARCHAR(100) NOT NULL, -- enum: user_login, grade_created, grade_override, plagiarism_flag, etc.   actor_user_id UUID REFERENCES users(id),   resource_type VARCHAR(100),   resource_id UUID,   action_details JSONB,   ip_address INET,   created_at TIMESTAMP DEFAULT NOW(),   INDEX idx_audit_tenant_event (tenant_id, event_type, created_at) ); `  ---  ##
